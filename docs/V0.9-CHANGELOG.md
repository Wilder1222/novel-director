# v0.9：阶段作品与逐项核验

Director 0.9.0 / Studio 0.3.0。研究和方案先于实现，见 `research/2026-10-22-v0.9.md` 和同日 plan。

- 新任务按八种意图裁剪阶段，不把审稿或大纲扩成整章创作。每阶段保存实际可读作品、必需维度索引、准确引文的逐项审查、真实宿主回执；作者不需要填写 JSON。
- 上游作品/审查、故事资料/正式正文、规则、当前 Run 候选/审稿及定向修订验收换版，相关下游结论过期。历史版本与失败报告保留。
- 托管章节的底层 Run、ensemble 和 assembly 同样检查前置阶段；已托管流程不能只换 Run 或把 checkpoint 写成 completed 来跳过。正文/修订一次管理一章，多场景可组章，不承诺批量正式发布。
- 排练来源必须对应完成场景及完整候选；正文必须是完整 Run 全文；审稿有实际报告全文、六维原文证据且阻塞/重要问题闭合。修订从诊断原稿派生，经定向验收后再审稿。实现与验证绑定实际差异/日志文件。
- 每阶段最多3个作品版本、每版3次审查，耗尽后保存停止点和新策略，显式替代而不无限重试。大包拒绝截断，需缩小任务。
- 原项目 schema、Run 0.5、ensemble 0.7 不变。未启用旧章节保留 legacy_unverified；新任务通过 Skill 默认启用。原有作者批准、正式覆盖备份和发布检查继续生效。

确定性通过、证据覆盖、语义审查满意和作者批准分开。主会话仍需真实核对来源与审查质量；本地回执不是身份认证，模型审查不是外部读者验收。synthetic_test 仅验证工程分支，不能从托管流程批准/发布。严格角色隔离仍按宿主实际能力判断，本版本不宣称已解决宿主不能禁止子代理文件读取的问题。

恢复与命令见[阶段流程](../.agents/skills/novel-director/references/staged-workflow.md)。
