# 悬疑推理与伏笔工程

## 五层信息状态

- 作者真相：事件在各历史版本中的真实因果；保存在私有规划中。
- 物证：角色可以获得的实际记录，写明谁、何时、如何获取。
- 角色判断：有限证据下形成的推论，可能错误，且不等于真相。
- 读者已知：正文实际披露的信息；不能假设读者看过作者大纲。
- 尚未揭示：计划兑现的信息，不能在普通正文阶段泄露。

## 设计一个谜题的步骤

1. 写下确定或临时的正确答案和隐含的人物动机。
2. 倒推必要事实：若答案为真，哪些物证或行为必须发生？
3. 为关键结论设置多条独立支撑线索，避免缺一条线索整条推理就无法成立。
4. 设计至少一个基于真实证据的合理误读；不是篡改真实记录来强行反转。
5. 依章节安排“第一次出现 → 角色误读 → 反证 → 重新解释 → 完整兑现”。
6. 确认人物获得线索的能力与身份可信：20岁大学生不能无缘无故进入绝密系统。

## 真相兑现约束

本卷中心谜题须在本卷给出重要答案，世界观层级可以跨卷。新真相必须能解释已经出现的证据，而不是凭空添加超能力/全知配角。不要把“其实一切都是梦”用作没有准备的最后一刻逃逸解释。

## 伏笔表最少字段

`id / question / setup_chapter / payoff_chapter / observable_evidence / plausible_misreading / truth / affected_history_ids`。

## 公平推理测试

- 隐藏人物或装置可以尚未出场，但真正解决谜题的**关键机制**必须提前有迹可循。
- 不随意让 POV 角色已想明白却对读者隐瞒其推理；如作此处理，需要明确叙事约定。
- 检查线索在不同版本的存在条件，普通证据应随其版本变化；特殊档案物件需要先设定保留原理。

方法来源：Reedsy mystery craft guide https://reedsy.com/studio/resources/how-to-write-a-mystery/ ；Sanderson Promise–Progress–Payoff；Three Clue Rule（本用于互动叙事，改造为小说线索冗余启发）。
