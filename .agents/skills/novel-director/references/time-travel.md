# 时间旅行与多历史版本严格审校

本模块用于《昨日归档》及其他双穿、循环、平行历史故事。**先明确采用什么时间模型**：单一自洽、可改写历史、多世界分支等不得未经说明混用。示例采用“有限节点下可改写历史 + 受保护记录残留”。

## 五本账必须独立维护

1. **客观时间账**：每个事件在其 `history_id` 中发生的年、月、日、时、分。
2. **旅者主观时间账**：旅者从出发至返回实际经历多少小时，身体如何老化。
3. **历史版本账**：如 H0、H1 的分歧事件、父版本、哪些物理事实被改写。
4. **知识账**：角色当时已经知道什么，消息从何处获得；保留记忆不等于全知。
5. **物证账**：每份照片、信件、硬盘、纸质档案属于哪个版本，是否具有免于覆盖的特殊保护。

## 《昨日归档》项目示例约束

- 在2032-10-20，陈叙、许知微均为20岁；具体生日为样例临时补足，非用户已确认事实。
- 20岁的陈叙从2032进入2009；2009年正常生理时间中他尚未出生。他存在于2009的证据必须追溯到穿越事件。
- 20岁的许知微从2032进入2041；2041年若存在29岁版本的自己，必须写明二者是否同时在场、如何避免被发现或接触。
- 单次停留不得超过72小时；初始示例从10月20日20:17出发，到10月22日20:17返回，两端主观历时48小时。
- 2009普通纸质记录可能自然保存到2041，从过去到未来单向传递；未来向过去的信息传递必须有独立有据的载体、途径或特殊归档规则。
- 历史改写不是抽象的“代价守恒”。修改父母相遇、职业和生育链可能令人物不再出生，必须能描述可追踪的因果链。

## 逐章必问

- 本章节的角色年龄、衣着、装备与实际经历是否匹配？
- 哪些历史版本的事实只对该版本成立？
- 若角色亲历过两版历史，他何时获得了保留旧记忆的条件？
- 此处出现的录像/纸张/通信，保留了哪个版本的信息？
- 在写此行动时，角色能否知道结果？如不能，为什么会做这个决定？
- 哪个事件是本次改写的必要原因？改变后哪些已经出场的人会受影响？

## 三类矛盾

- 硬错误：72小时违约、出生日期与既定年龄矛盾、历史版本 ID 无来源、同一场景出现无解释的两处同一身体。
- 高风险：历史改写规模不合理、人物动机不充分、旧档案载体缺乏保护机制。
- 文学可能性：作者故意安排的时间悖论或不可靠证词，仅可标注待核，不自动认定错误。

Python 脚本可验证出生年份、停留时长、已编码知识、伏笔先后；它**不能自动证明**整部时间旅行叙事无悖论，深层因果图需由时空审计者分析。
