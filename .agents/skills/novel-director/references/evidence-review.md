# V0.5 · 有依据的审稿，而非只填“证据”二字

## 输出契约

每个问题或评分必须有 `evidence`（审稿解释）与非空 `citations`（原文定位）两部分。不要把解释塞进 quote。一个合法的最小审稿：

```json
{
  "reviewer_type": "agent",
  "issues": [],
  "scores": {
    "emotion": {
      "score": 3,
      "evidence": "人物通过暂缓承诺体现有限合作；此处判断仍需作者审阅。",
      "citations": [
        {"source": "candidate", "quote": "她没有答应。"}
      ]
    }
  }
}
```

`quote` 必须真的存在于该次候选稿。若一个短语出现多次，提供 `start` 和 `end`，采用 Python 字符串的 `[start:end]` 范围。单位为 Unicode 码点，不是字节、中文“字数”、UTF-16 单元。工具不消除空格、不改标点、不做模糊匹配。回车换行也是原文的一部分。`source` 可为 `candidate`，也可为白名单内的 `canon.json`、`bible.md` 或 `manuscript/V01-C01.md` 等相对路径，不能读取任意文件或 `.env`。

提交时自动保存来源 SHA-256、行号和字符范围；已提交引用再次使用时，源文件的任何字节变化均使它过期。摘要绑定的是整个来源，而不只是摘录，因此即使摘录没变、其他内容变了也要求重新核实。

## 三道核验

`run-review` 先验证结构，再定位所有引文；`run-approve` 重新读取来源，核验审稿摘要及创作契约；`run-publish` 再次核验来源、正文、审批与故事资料快照。不能仅把 evidence_audit.verified 手填为 true 来绕过。

无问题、无评分的报告也需要 `summary_citations`，说明实际阅读范围，而不能提交空 `issues` 就结束审稿。只有大纲引文而没有候选正文引文也不能通过。

## 缺席判断和跨章审稿

“没有铺垫”不是某一短句可以严格证明的命题。应在 evidence 中声明查阅了哪些章节、预期看到什么，附关键上下文引用，结论标为需人审的解释。V0.5 不自动证明一个事实在全书缺席，也不证明引用能支持评论。发现原文引用与评论关联很弱时，作者必须驳回，即使脚本已通过。

先列最大影响的问题，再做语言润色。允许没有问题的章节，不以挑错数量论绩效。审稿不得为了符合格式擅自新增人物年龄、隐藏设定或自动修改正式正文。

## 旧版升级

V0.4 的未完成 Run 必须以原候选稿创建新的 V0.5 Run、提交新审稿，再批准。旧版的无结构引用报告不会自动成为可信证据。旧正式正文原样保留，项目数据 schema 继续兼容0.1至0.4；0.5是工具/审稿协议版本，不是假称已对全文做过新审校。
