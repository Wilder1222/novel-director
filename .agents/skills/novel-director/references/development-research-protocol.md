# Novel Director 研究先行迭代协议（所有后续版本强制）

适用：所有新增模块、新创作机制、破坏性 Schema 迁移、Agent 路由、评测标准修改。

## 不可跳过的研究门槛

1. **先核对上一版：**版本、真实测试结果、没有实现的假设、用户刚确认的 Canon。绝不把想象中的现有功能当成已实现。
2. **公开小说创作案例：**优先查近12个月权威行业报告和透明榜单，至少覆盖2种不同类型案例；榜单类型（影响力/订阅/收藏/热度）不得混淆；记录作品、来源、时间、采用理由和不适用边界。未实际阅读全文时不得声称“逐章研究全书”。
   作者当前硬要求：**每部采用作品实际采集20–50个不同完整章节**；本轮10部热门历史/玄幻/仙侠为主的专题，各至少20章完整细读。分别登记目标与缺口，正常公开/授权来源、版本/章号/URL/清洗规则/LN及Unicode版本/正文摘要要能核对。付费、预览、目录或不可可靠解读正文不算；不得跨书合计或拼平台版本。参考索引见reference-library.md；研究stage-start声明reference_books，research来源绑定reference_samples实际清单、raw来源及细读档案，独立核验collection和claim_scope。采集数量不等于语义审读数量，方法推论须限定到真实读过的章/段。每章有事件/人物/情感/细节/铺垫/承接分析和两段短证据，技巧有适用前提、局限与原创练习；实际复审无未决才记完成。旧schema1保留原50章证据范围，不倒填新结论。
3. **写作四维诊断：**世界观（规则、限制、社会关系、代价）；情节（任务、阻碍、因果、转折、兑现）；人物（外在目标、内在矛盾、选择、成长）；情感（关系状态、误读、共同经历、付出代价、修复）。如涉及悬疑补“公平证据/误导/回收”，如涉及影视补“可拍动作/场次/节拍”。
4. **论文/写作教材：**至少一项可信研究或一手创作访谈；说明研究样本（短篇、电影、学生写作、AI 生成）与本项目百万字长篇的外推限制。
5. **开源对比：**至少两个现存小说或剧本 Skills，确认 README/SKILL.md/测试/维护状态。只借鉴抽象设计，未验证授权时不复制代码与长篇原文；谨防将对方 README 功能宣称当成我们已经实现的能力。
6. **写研究记录：**在任何代码编辑前，写 `research/<cycle>.md`，列出来源 URL、已证事实与个人设计判断、方案选择、失败案例、验收测试、现有项目兼容性。
7. **实施和回归：**新增功能以失败测试驱动，保护已有作者数据；正向/反向用例都通过，再做实际接口示例。按作者最新要求，软件历史版本不备份，只保留最新版本；替换前核验新产物、替换后核验实际安装，不创建回滚副本。不能用合成测试冒充真实小说验收。
8. **如实汇报：**区分确定性校验、模型评分、读者验证；不得用自动测试数量证明小说优秀。注明哪些是计划、哪些是可用脚本、哪些需要宿主 Agent 与作者决定。

## 版本输出标准

- 带日期和来源的研究档案；一份变更说明与风险列表。
- 可独立安装的 Agent Skill ZIP；含 `SKILL.md`, `references/`, `scripts/`, `assets/`, `agents/`。
- Python stdlib 命令和最小运行案例，保持原稿不被覆盖。
- 可重建的测试与测试报告，包含失败项和未覆盖项。
- 一个新版本不等于开始自动后台任务；用户明确要求定期运行时才考虑计划执行。

## 研究范围边界

严禁：复制热门作品情节充当原创；从未授权的全文抓取私有章节；照搬在世作家独特文风；把现有 AI 评分伪称为读者认可。研究可参考作品的公开内容、评论和方法级抽象。
